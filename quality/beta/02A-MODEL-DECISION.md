## Baseline inspected

The current daily reducer is deterministic and replays from `RunConfig` plus frozen `envSeries`. Before this work, `modelInputs.model: 'run-inputs-v1'` already existed as a serialized input-shape tag; it did not identify the crop equations or parameter set. `cropModelVersion` is the separate discriminator added by this stage. Legacy records may omit `modelInputs`; `engine.ts` then falls back to caller context or today’s crop catalog. Existing development is run-window normalized in `drivers.ts` (`growthDays × meanDailyGddC`), biomass is `gddAccum / gddRequired`, the water bucket uses a universal 30 cm root depth, and catalog yield is paid independently of accumulated dry matter. `DailyEnvironment` may include natural DLI; enclosure climate can combine natural and installed DLI, while `dliAvailable` distinguishes unknown light from known zero.

The current `cropThermalParams.ts` has nine crop entries. It is useful source evidence, but does not yet cover production, root-zone, nutrient, cultivar, or every catalog parameter. `growth.ts` remains a second calendar-day projection path and must be labelled/kept separate until its consumers are migrated.

## Decisions

### D1. Keep a pure local daily model and use explicit model dispatch

Implement a new crop-model version in the existing TypeScript reducer. Keep `stepDay`, `simulateRun`, frozen environment series, and the existing storage/API seams. Do not add a Python runtime, server requirement, worker framework, or second run store.

Each new run must freeze both a named model version and the complete parameter/input version it consults. Dispatch is explicit:

| Stored record | Replay behavior |
|---|---|
| Explicit v1 model + frozen v1 inputs | Replay the old equations unchanged. |
| Missing model discriminator but complete v1 frozen inputs | Treat as the named legacy v1 semantics; never reinterpret it as v2. |
| Missing discriminator and missing frozen crop/model inputs | Mark historical replay unsupported/qualified, preserve the stored summary and input artifact, and do not recompute or overwrite it from the current catalog/context. |
| Explicit but unknown model/parameter version | Report unsupported with an export path; preserve the stored summary. |
| Explicit v4 model + complete v4 frozen inputs | Replay the isolated two-pool canopy-production path as qualified synthetic software behavior; incomplete inputs remain unsupported and preserve stored summaries. This is not a general crop parameter set. |
| New runs while v2 is not runnable | Continue using v1 with frozen v1 inputs; do not store a v2 placeholder summary. |
| New runs after the v2 daily reducer and acceptance gates pass | Use v2 and freeze every model-driving value, provenance, unit, event/method and fallback status. |

A migration cannot invent a user’s original measurements. If current run creation or playback cannot identify this state without changing summary semantics, that migration is part of the implementation gate; do not silently substitute live context.

### D2. Separate development, dry-matter production, and harvestable yield

Phenology uses crop-specific thermal response and fixed referenced stage/maturity targets. The source-defined accumulation method, start event, cultivar range and endpoint travel together. A run-window mean must not set a crop’s thermal target.

Daily net dry matter uses the LINTUL-family radiation-use-efficiency structure:

`ΔDM = RUE × intercepted PAR × supported stress factors`

The implementation must state units for every term and convert DLI/PAR explicitly. RUE is net dry-matter efficiency under its documented reference conditions; do not also subtract an unparameterized maintenance term and double-count respiration. Where maintenance/reserve dynamics are material (especially perennial/repeated-harvest crops), expose the limitation and defer the different lifecycle state contract to 02D. Dry matter and reproductive allocation/harvest index are separate. A catalog fresh-yield ceiling is not a biomass model or a harvest index.

Known zero usable PAR yields exactly zero sustained photosynthetic dry-matter gain. Germination reserves require explicit initial reserve state, finite reserve amount and an accounting event. Unknown PAR remains unknown and cannot be silently treated as sufficient. The result must be visibly incomplete/qualified or use a documented, provenance-tagged fallback only when its parameter source and domain are recorded. Fungi use a separate substrate/lifecycle model and never plant photosynthesis.

### D3. Use FAO-56 as the soil root-zone water method, within its supported input domain

For soil-grown crops, use the FAO-56 root-zone balance as the method reference: available water is based on AWC and effective rooting depth; stress begins relative to readily available water; water entering, extracted, draining and running off must reconcile in mm. Root-depth development and depletion fraction are crop/model parameters, not a universal 30 cm constant. The run must freeze those values.

This is a single effective root-zone storage model, not a layered Richards solver. If a necessary soil/media, root-depth, runoff, or water input is unavailable, expose the estimate/fallback and uncertainty. Do not call the current coarse nitrogen pool a solution-chemistry, pH, salinity or oxygen model. Soilless resource balance requires the 02B hydro/resource contract and must not be silently mapped to a soil bucket.

`quality/beta/evidence/fao56-root-reference-coverage.json` records the FAO-56 Table 22 maximum effective root-depth ranges and depletion fractions for 19 exact/common catalog crop matches, plus explicit unresolved status for every other catalog crop. These are source-reference values only: the range is not an initial depth or growth trajectory, and the p value is listed at ETc approximately 5 mm/day. The source notes that p may shift 5–10% with soil texture; that adjustment is not inferred here. No source artifact digest was captured. The inventory does not create an active model default or establish crop-model completeness. It preregisters the source's ten-day Example 37 as a fixed-p arithmetic reproduction fixture; this checks the FAO-56 helper against source-displayed arithmetic, not the complete crop reducer or any prediction.

### Preregistered A-05 follow-up: water-limited crop transpiration in enclosures

`quality/beta/evidence/fao56-environment-v2-transpiration-coupling.json` preregisters a separately versioned `environment-v2` path; `environment-v1` replay stays unchanged. A two-tick fixture verifies tick two uses tick one's computed room ET factor. Root-depth growth uses the prior room's temperature driver, or outdoor temperatures on the first day, and its boundary storage is included in the same root-zone balance. The environment-v2 input snapshot freezes the archetype, equipment, calibration overrides, outdoor defaults, and initial room state; only complete crop-model-v4/run-inputs-v4/environment-inputs-v2 records replay. Local save/list and mocked REST round-trip tests preserve the new config fields and a distinctive stored summary; they do not establish native browser-transaction or live-server persistence. This is not climate calibration, predictive comparison, or biological validation.

## D6. Keep germination, field emergence, and transplant establishment distinct

The existing v2 direct-sowing behavior starts crop thermal development, photosynthesis, root-zone water use, and stress on the sowing date. That behavior is retained only as the frozen historical `crop-model-v2` contract; it does not pass the 02A establishment acceptance gate. V3 gates crop photosynthesis, root-zone uptake/transpiration, dynamic root-depth development, plant nutrient uptake, and plant stress until the frozen observed emergence or transplant event. Radicle growth before emergence is outside the current crop-root process. The soil water store may receive weather and irrigation before emergence, but it cannot remove crop water. V3 maintains a source-event thermal clock from the frozen sowing/transplant event for the source maturity endpoint and a separate emergence-relative physiology clock. The source clock never drives intermediate crop stages. No source-supported stage map is available: v3 stage remains unavailable throughout the run, including after the separately reported maturity endpoint, and its 3D plant stays at the smallest juvenile authored pose for the entire run. This is an illustrative placeholder, not a simulated growth trajectory. Stage observations on v3/v4 remain recorded but are neither assimilated nor scored because no source-supported intermediate-stage mapping exists; the run reports this limitation. Manual v3/v4 harvest is accepted only after the frozen source maturity endpoint.

For a direct-sown crop, a v3 run must freeze either (a) an observed emergence date with an explicit above-ground dry-matter state at emergence, or (b) a complete crop/seed-lot emergence model and its daily seedbed inputs, followed by an explicit post-emergence state. Missing emergence or initial state makes the record unsupported and preserves any saved summary. Germination and hypocotyl/shoot elongation are separate processes. No photosynthetic production or crop root-zone uptake/transpiration, dynamic root-depth change, or plant nutrient uptake is allowed before emergence. A fixed effective root-zone depth may be used only as a qualified frozen approximation. Dynamic root development for delayed direct sowing requires a separate frozen profile explicitly indexed to emergence and a root depth at emergence; the existing sowing-start Yuma profile cannot be shifted to emergence without evidence. Seed-reserve-driven change is permitted only when a finite reserve is frozen and the daily transfer is separately accounted; this slice does not assume or infer seed reserves.

For transplanting, the transplant date is the crop start event, but a crop-level default initial mass is insufficient to describe varying nursery age/size. A v3 run must freeze measured or explicitly assumed per-cell above-ground dry matter at transplant, in the model's units, plus any source-supported initial thermal state when the source clock requires it. A missing initial state makes the record unsupported. WOFOST's `TDWI` is total crop dry weight in its own crop model and is partitioned at emergence; it cannot be copied into this model's above-ground transplant mass. No generic transplant mass is inferred from leaf count or a different cultivar/environment study.

The available primary bean sources delimit what can be claimed. [Raveneau et al. (2011)](https://doi.org/10.1017/S0960258511000067) report common-bean germination base temperatures of 5.1–9.6 °C depending on seed lot, and report shoot-elongation bases 3–6 °C higher than germination bases; these are controlled laboratory responses, not field-emergence thresholds. [Moreau-Valancogne et al. (2008)](https://doi.org/10.1016/j.eja.2007.09.003) report four Booster seed lots, final field emergence of 56–90%, and emergence durations of 9–28 days across French field situations; seedbed temperature/water, sowing depth, aggregates, and crusting affect the outcome. Its SIMPLE model needs seed-lot and layered daily seedbed inputs. The study is only a potential emergence-specific holdout if exact treatment observations and complete daily seedbed inputs are acquired and no FarmFriend emergence parameters are fitted or corrected against those outcomes. These observations are not general bean parameters. [WOFOST 7.2 system documentation](https://wofost.readthedocs.io/en/stable/_downloads/a552f9d445b6dd13f7db99ec29b64f0b/WOFOST_system_description.pdf) (de Wit, Boogaard, Supit and van den Berg, editors; May 2020; CC BY 4.0) provides a method reference, not parameters transferable to this model: it uses crop-specific `TSUMEM`, `TBASEM` and `TEFFMX`, and defines `TDWI` as initial total crop dry weight in kg/ha, partitioned within WOFOST at emergence. None of these sources supplies a reusable transplant initial-mass value.

## Implementation checkpoint

The current implementation preserves v1/v2/v3 behavior and adds v4 frozen-input support; persisted paths that would otherwise recompute from a live crop catalog or soil context are unsupported and preserve stored summaries. The qualified v2 daily path for complete frozen inputs computes fixed-source thermal development, light-driven above-ground dry matter, harvestable dry matter, and a single effective FAO-56 root-zone balance.
